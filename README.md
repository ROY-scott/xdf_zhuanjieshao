# 学员转介绍推荐登记

面向培训机构招生场景的**转介绍信息采集工具**。教师登录后填写推荐信息，数据实时汇入云端；管理员按权限查看汇总并导出 Excel。

线上地址：https://xdf-referral.app.workbuddy.host/

## 功能

**填写端（全体教师）**

- 邮箱注册 / 密码登录 / 邮箱验证码登录
- 注册邮箱限定 `@xdf.cn` 后缀
- 录入字段：推荐人姓名、推荐人电话、推荐学员姓名、年级、科目（多选）、备注
- 推荐时间在提交时自动记录（由数据库 `DEFAULT now()` 盖章，不依赖客户端上报）

**管理端（白名单管理员）**

- 汇总列表、关键词搜索、删除错单
- 一键导出 Excel / CSV
- 统计面板：累计推荐、今日新增、近 7 天、涉及学员数、推荐人数、参与老师数

## 权限模型

三层，且**拦截发生在数据库层**，不依赖前端隐藏按钮——手工构造请求同样读不到数据。

| 角色 | 能力 | 约束方式 |
|---|---|---|
| 未登录 | 无 | 所有表拒绝匿名访问 |
| 已登录教师 | 仅提交 | `owner_id = auth.uid()`，且邮箱后缀须为 `@xdf.cn` |
| 管理员 | 查看 / 删除 / 导出 | 需存在于 `app_admins` 白名单 |

## 技术要点

- **纯前端单文件**：`index.html` 内含全部结构与逻辑，无构建步骤、无打包工具
- **零外部依赖**：不引用任何 CDN 上的 JS 库或字体
- **Excel 导出为手写实现**：自建 CRC32 查表 → ZIP（store 模式）→ 最小 OOXML 包，不依赖 SheetJS 等第三方库，断网环境同样可用

## 目录结构

```
index.html   单文件应用（结构 + 样式 + 逻辑）
logo.png     页头品牌标识
```

## 部署

1. 目录保持干净（只放 `index.html` 与 `logo.png`），避免无关文件被一并上传
2. 通过平台的「发布为应用」发布为静态站点
3. 云服务的 `endpoint` 与 `publishableKey` 位于 `index.html` 顶部的 `PUBLIC_CONFIG`；**这两个值由云服务环境下发**，更换环境时必须同步替换，否则登录与数据读写会因域名不匹配而失效

## 注意事项

- `publishableKey` 会随页面公开，但它**本身不含权限**——服务端另有域名（Origin）精确匹配校验
- 数据库启用了行级安全（RLS）。调整策略前先查看现状；**策略与授权是两道独立的门**，漏掉 `GRANT` 会得到形似"策略失效"的权限错误
- **修改 Excel 生成器后必须用严格解析器校验**：OOXML 对父子元素的顺序有强约束（例如 `autoFilter` 必须排在 `mergeCells` 之前）。顺序错误会让 Excel 直接判定文件损坏，而宽松的解析库发现不了这个问题
